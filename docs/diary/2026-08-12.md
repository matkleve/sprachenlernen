## Idea evaluation: same-session requeueing — "how is the feedback saved"

**Change class: Trivial (docs only).** Owner clarified the same-session
requeue idea (`docs/IDEAS.md`, 2026-08-12 entry) is Anki-style self-grading
throughout — no typed/checked answer was ever proposed, correcting my
misreading in the prior pass — and asked specifically how a same-run repeat's
outcome gets saved.

Resolved without new design: every attempt (including same-run repeats)
still writes one `review_log` row via the existing shape; "needed more tries
→ comes back sooner" is not a feature to add, it is `stabilityAfterLapse` in
`lib/scheduler.ts` already lowering `stability` on an `again`/`hard` grade,
which FSRS already turns into a shorter next interval. A flat "3 or 8 days ±
randomness regardless of tries" alternative would be a downgrade — it drops
the per-card signal FSRS was chosen for. The only genuinely new piece is the
within-run position ("back in ~5 cards"), which has no FSRS equivalent
(shortest native gap ≈0.49 days) and must live as session-local client state,
never through the scheduler. Also corrected: the earlier "two clocks confuse
trust" objection doesn't hold — no due date/backlog/badge is ever shown to
the user (`review-session.md`, `words-home.md`, `words.md`, UC-006), so there
is only one visible clock and nothing for a same-run mechanic to compete
with. Still `🆕 unevaluated` — no use case named yet, no code changed.

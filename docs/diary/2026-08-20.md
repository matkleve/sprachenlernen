## Security audit — ten findings, all fixed (2026-08-20)

**Change class: Sensitive** (auth, deletion, persisted data). Red-test-first on
every finding with a code path; full `verify` green, justified by
VERIFY-SCOPES.md ("auth, DB, or persisted data paths touched").

Two were exploitable, and the rest were the conditions that let those two sit
unnoticed.

1. **`deleteAccount` trusted the session cookie.** `getAccount()` →
   `getSession()` verifies no signature, and the id went to the service-role
   client, which bypasses RLS. A self-made cookie deleted any account. Fixed
   with `getVerifiedAccount()`. The red test printed `deleteUser("victim")`.
2. **Open redirect** in `/auth/callback` — `next.startsWith("/")` accepts
   `//evil.com`. Fixed with `safeInternalPath`.
3. **CI handed the service-role key to every `pull_request` run** of a job that
   executes PR-branch build scripts. Split into an environment-gated job.
4. **BACKEND.md §8 gates were prose.** `scripts/check-secrets.mjs` now exists
   and runs in the default scope.
5. **No security headers at all.** ADR-0013; `form-action` deliberately absent.
6. `create-test-user.ts` sat in the repo root with the elevated key and a
   literal password → `scripts/`, env-supplied, refuses production.
7. `task_state` update filtered on `task_id` only (BACKEND.md §4).
8. `content_sources.body` had no ceiling; `card_content_flag.note` next to it
   had 280. Now 100 000, in adapter and constraint.
9. "Complete archive" was the review log plus an email — UC-024 says
   everything. Four more tables now.
10. `/login?error=` rendered arbitrary URL text on the real sign-in form. Codes
    now, resolved from `messages/*.json` — which also stopped German learners
    being shown English errors.

New traps recorded: `getSession()` verifies nothing; `startsWith("/")` is not a
path check.

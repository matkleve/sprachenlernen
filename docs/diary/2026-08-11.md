### What an audit of that work found before it landed

Four things, fixed in the same change rather than filed:

1. **The spec's own acceptance criterion was false.** `back !== lemma` failed
   for six cognates, and *no test enforced any of the five new criteria* — the
   AC file was prose. Now: six tests, shown red against the original deck.
   The criterion itself was the wrong shape — a true cognate satisfies its
   intent and violates its letter — so the exceptions are listed as data in
   `es-meaning-recall.cognates.json`, read by both the script and the test.
2. **Machine glosses shipped as dictionary sense lines.** `perro` was *"dog (the
   species Canis familiaris (sometimes designated…"*; `amor` was *"a surname"*;
   `venir` was *"Senses relating to literal movement."* Shaping now removes the
   bracketed apparatus and **nothing else**, and a gloss that is still too long,
   empty, equal to its front, or a grammar note **fails the build** naming the
   lemma. Mean back length 22.7 → 12.1 chars, 20 hand overrides.
3. **Proper names, artefacts and inflected forms were in the pool** — `john`,
   `jack`, `afuerar` (not a Spanish verb, and it had been given a hand-written
   gloss rather than removed), plus `dio` and `vi`, which are the preterites of
   `dar` and `ver` — both already in the pool at their own ranks, so the deck
   held two cards for one verb under different `wordId`s. Now
   `es-meaning-recall.exclusions.json`, applied *before* the cap so the pool
   stays 500 and reaches one rank deeper instead.
4. **A 10× pool changed two surfaces the PR did not touch.** `/words` rendered
   the atlas unpaginated — 500 rows. Capped at 100, with both numbers named.
   And `listReviewsForTaskIds` sent the whole pool through PostgREST's
   `in.(…)`, which rides in the query string: **~13 KB raw, ~19 KB encoded**,
   past a typical gateway's request-line limit. Batched at 100 and re-sorted
   across batches, because `rebuild` is order-dependent.

**The trap worth keeping** (and now in `TRAPS.md`): every test around that query
stubs the client, so the gate stayed green at any pool size. Growing a data file
is not a data-only change — it is a change to every query that spans the file.

### And what the adversarial review of *that* found

Worth recording because the first fix was worse than the bug in one place.

The original shaping kept the first `;` group and the first three synonyms.
That is a **positional** rule over a source that does not order senses by
usefulness, so it discarded the right answer and left a fluent wrong one:
`policía` shipped as *"Civility, polity, public order"* — one position short of
*police* — and `gran` as *"apocopic form of grande"*, dropping the *"great,
grand"* that came after the semicolon. 61 cards had content cut this way.
Strictly worse than not shaping at all, and invisible to all three gate checks.

Shaping now removes bracketed apparatus and nothing else; 12 cards exceed the
length cap afterwards and got hand glosses. **The general lesson: a cleanup rule
that picks between alternatives is a guess wearing a heuristic's clothes.**
Removing what is always secondary (a parenthetical) is safe; ranking what is
sometimes primary (a sense) is not.

Four more, all fixed: the exclusions list had no test and the build script is
not in `verify`, so it was enforced only when someone regenerated (now exported
through `lib/starter-deck.ts` like the cognate list); `exclusions.json` failed
*open* if written as an array — `Object.keys` would have yielded indices and
filtered nothing while printing "wrote 500 cards" (both companion files now
fail closed on the wrong shape); batching lost the de-duplication a single
`.in()` gave for free, so a repeated task id would have replayed a doubled
history; and the atlas `<Table caption>` still said "each word in your deck"
over 100 of 500 rows, which is the accessible name.

One claim in the previous commit message was also wrong: re-ranking orphans no
history, but **excluding does** — `dio` and `vi` leave stored rows unreadable by
`listReviewsForTaskIds`. Same-day, so nil impact, but the spec now says it.

### What "reproducible" does and does not mean here

`kaikki.org` is blocked by the agent network policy, so the deck was rebuilt
from a **reconstructed** cache — the raw glosses the previous build had already
resolved, replayed through the new shaping rules. Rebuilding is byte-identical
*given that cache*, which is a weaker claim than it sounds like, and worth not
blurring: the first run on a machine that can reach Kaikki is the real test, and
it may surface lemmas needing an override that this one could not see.

The script now prints its cache size and the hand-checked/machine split, so the
distinction is visible rather than assumed — a reconstructed cache reports
`0.0 MB` where the real dictionary is hundreds. Flagged in the spec's Open
section as a precondition for stage 2.

### Italian, asked for and not built

Asked to do "the same for Italian". Did the investigation, built nothing, and
that is the result rather than a failure to deliver: three independent blockers,
none of which is code. Detail in
[`specs/service/starter-deck.second-language.md`](../specs/service/starter-deck.second-language.md).

What works is most of it. The same ranking pipeline runs on `data/frequency/it.txt`
and `data/lemma/it.json` untouched and yields **3,135** lemmas — enough for stage
1 and stage 2 — with a correct-looking head (`il, essere, e, avere, non, che …`)
and only 6 of the top 500 failing to resolve. Glosses are unreachable
(`kaikki.org` refused by the network policy, no licensed substitute found), and
nothing in the app knows what a *learning* language is — `I18N.md` is about
interface copy, which is a different axis at stage 0.

**The finding worth the trip** is the second blocker, which nobody had recorded:
the Italian frequency list carries accented and unaccented spellings as separate
entries, and the unaccented one frequently wins. `perche` (489,341) outranks
`perché` (417,508), with `perchè` a third entry at 71,521 — one word, three
ranks. `così` and `cosi` are near-even and the misspelling is ahead. 91 folded
groups are affected, so every accented Italian word's frequency is understated
by an unknown amount, and the ranking is wrong before glosses are even reached.

It cannot be folded blindly, which is the trap worth remembering: `e`/`è`,
`si`/`sì`, `se`/`sé`, `da`/`dà`, `ne`/`né`, `te`/`tè` are **genuine minimal
pairs**, so a normalise-and-merge pass would destroy six real distinctions to
fix eighty-five misspellings. It needs a per-group ruling from someone who reads
Italian, and merging re-ranks everything — a calibration event with provenance.
Spanish is clean here by luck of orthography: `más`/`mas`, `sí`/`si`,
`está`/`esta` are all distinct words, so the same pipeline was trustworthy.

**No Italian scaffolding was committed** — no generalised build script, no empty
`it-*.json` companions. Machinery for a pool that cannot be produced is
anticipation, and `AGENTS.md` is explicit that the second consumer is what earns
the abstraction. The script generalises in an afternoon once the blockers lift.

### The RLS suite has never run in CI

Found in the same audit, unrelated to the pool. `lib/db/access-control.test.ts`
skips itself unless three Supabase secrets are present, and
`.github/workflows/verify.yml` passed none — so the suite `BACKEND.md` §8 calls
"the single highest-value test in the product" has been reporting green on five
tests it never executed, on every PR since T-B8.

The workflow now forwards the three secrets. This changes nothing while they are
unset: GitHub renders a missing secret as an empty string, `hasLiveProject` is
`Boolean("")`, and the suite skips exactly as before — verified locally, 468
passed, 6 skipped either way. **It is half a fix.** Adding the secrets in
Settings → Secrets is the other half and needs the owner; without the passthrough
that step would have silently done nothing, which is the failure worth avoiding.

The pipeline's ceiling is **2,953 lemmas** — that is how many unique lemmas the
5,000-form frequency list resolves to. Stage 2 fits; stage 3 needs a bigger
list, which is a provenance and recalibration event, not a script change.

# 2026-07-31 — Base project set up

First entry, and the worked example of the format. Real events from building
this repository.

## Shipped

| Area | What |
| --- | --- |
| Instructions | `AGENTS.md` as the single instruction file, under 150 lines, with progressive disclosure into `docs/` |
| Process | Change classes, DoR/DoD, the eight-stage loop, state-coherence contract |
| Gates | `npm run verify` — types, lint, specs, tokens, contrast, tests, build |
| Example | UC-001 / item-picker, demonstrating state coherence; Button with all five interaction states |
| Memory | `TRAPS.md`, `AGENT-PITFALLS.md`, this diary, three ADRs |

## Decisions

- **`AGENTS.md`, not `CLAUDE.md`** — chose the open standard over the
  vendor-specific file so the rules cannot drift per tool. Rules out keeping
  tool-specific rule content anywhere; those files become pointers. ADR-0003.
- **Frontend-only to start** — chose no database over baking in Supabase. Rules
  out assuming a backend in `ARCHITECTURE.md`; the boundaries live in
  `BACKEND.md` as an optional module instead.
- **Colocation over categorization** — `features/<name>/` holds a feature end to
  end, rather than splitting it across `components/`, `hooks/`, `utils/`. A file
  is promoted to `components/ui/` only when a *second* feature needs it.
- **Instruction files stay short.** Research across a large repository sample
  found files past ~150 lines cost more per request without behaving better.
  Rules out the "one comprehensive file" approach used in earlier projects.

## Went wrong

- **The Button test failed: `cn("rounded-pill", "rounded-none")` emitted both
  classes.** It looked like `cn()` was broken. It was not — `tailwind-merge`
  only knows Tailwind's default scales, so a custom token like `rounded-pill` is
  a class it cannot classify, and a class it cannot classify is one it will
  never treat as conflicting. Fixed with `extendTailwindMerge` in `lib/utils.ts`.
  The check that caught it: the `className`-override test, which only exists
  because the Button spec has a criterion for caller overrides.
  → promoted to `TRAPS.md`. **Also affects the other projects** — same blindness
  there for `rounded-card`, `bg-pink`, `shadow-soft`.

- **`check-specs.mjs` derived the wrong expected spec ID** — it split
  `docs/specs/component/button.md` and took the second segment (`specs`) as the
  kind, producing `SPEC-specs-component-button`. Found by running the gate on
  the repo's own specs, first try.
  → no promotion needed; it was a bug in the gate, fixed in place.

- **Two specs, one missing back-link.** `SPEC-component-button` named UC-001,
  but UC-001 did not list it. Caught by the two-way traceability check, which is
  exactly the case it exists for — a one-way link reads as complete.

## Open

- The repository is not yet marked as a **Template repository** on GitHub, so
  `gh repo create --template` will not work until that is set in Settings.
- No branch protection on `main`, so `verify` is advisory rather than required.
- `GLOSSARY.md` has only the process terms. Its domain section is a placeholder
  until a real project fills it in.

Deliberately **not** taken:

  three stage skills plus one reviewer agent cover the same ground; five
  personas is vocabulary to maintain before it earns anything.
- **The two-line comment contract on every CSS class.** Written for a
  hand-authored SCSS codebase; with Tailwind the class *is* the description, and
  the rule would produce noise rather than signal.

### Went wrong

- **`check-tokens` flagged its own documentation.** The new `transition-all`
  rule fired on the comment in `Button.tsx` explaining why not to use it. The
  gate scans comments and is literal. Reworded the comment rather than reaching
  for the `token-check-ignore` hatch — suppressing a line to fix prose would
  have blinded that line to real hits later.
- **The `AGENTS.md` size warning fired at the intended steady state** (144 of
  150, warn threshold cap−15). A warning that is always on is one people learn
  to ignore — the same failure this repo documents elsewhere. Narrowed to cap−5.

## Design and code audit

Read the repo as an outside reviewer would, against its own goal. Four real
defects, two documented-but-unenforced rules, one design-system hole.

### Defects found

- **All three Button sizes rendered at the same height.** The base classes
  carried `min-h-11` (44px) alongside `h-8` / `h-10` / `h-12`. `min-height`
  beats `height` in CSS, so `sm`, `md` and `lg` were one 44px box. The variants
  were in the source, in the spec, and in the tests, and did nothing — the
  tests only asserted "renders". Fixed by separating the *visual* box from the
  *interactive target*: explicit heights, and a transparent `::after` that grows
  the target to 44px. Added a regression test asserting the three heights differ.
- **`@eslint/eslintrc` was used but never declared.** `eslint.config.mjs`
  imports `FlatCompat` from it; it only resolved because `eslint-config-next`
  pulls it in transitively. Declaring it added 7 packages, confirming it had
  been absent. A minor version bump upstream would have broken lint with an
  error pointing at the wrong thing.
- **`app/` had no `loading.tsx`, `error.tsx` or `not-found.tsx`** — while
  `ARCHITECTURE.md` and `AGENTS.md` both described the layout as "page, layout,
  loading, error". The docs described files that did not exist. Added all three;
  the error boundary logs rather than swallowing (Constitution §4) and the
  loading state is a skeleton with a live region, not a spinner.
- **The skip link could break silently.** `<main id="main">` lived in
  `page.tsx`, so any new page that forgot it would leave the skip link pointing
  at nothing — with no failure anywhere. Moved the landmark into `layout.tsx`,
  which makes it structurally impossible to omit.

### Rules that were documented but not enforced

- **Token ↔ tailwind-merge parity.** `TRAPS.md` explains that a token missing
  from `lib/utils.ts` silently loses its override behaviour, and then the
  countermeasure was "remember to edit both files" — which is exactly what
  fails. `check-tokens` now reads the `@theme` block and asserts every
  `--color/radius/shadow/spacing/ease` token is registered. It immediately found
  one: `--ease-out-soft`, added in this same session and never registered.
- **`## Check` was prose.** A spec could name a test that had been renamed or
  never written and still look complete. `check-specs` now resolves the pattern
  in `npm test -- <pattern>` against real test files, closing the third leg of
  use case → spec → test.

Both new gates were verified by breaking something and watching them fail,
before trusting them green.

### Deliberate duplication, made safe

`layout.tsx` has to repeat the canvas colour as literal hex, because the browser
reads `themeColor` from a `<meta>` tag before any CSS exists — `var()` cannot
work there. Rather than just excusing it with the ignore comment, `check-tokens`
now asserts the two values still equal `--color-canvas` in each theme. Proved it
bites by changing one and watching it fail.

### Design system

Added the **type scale** and **spacing rhythm** — genuinely missing, and a
design system without them is half a system. Which step means what, the 14px
floor for anything read as a sentence, measure guidance, and line-height
overrides in `globals.css` (Tailwind's defaults leave body copy too tight and
headings too loose).

## Open — top recommendation

**There is no form primitive.** `Button` exists; a `Field` (label, description,
error, `aria-describedby`, `aria-invalid`) does not. Forms are where
accessibility breaks most often and where every project re-solves the same
problem — precisely what this repo exists to prevent. Not built here because its
API depends on a decision that is the project's to make: controlled vs
uncontrolled, and whether it integrates a validation library. Worth doing before
the first real project, as UC-002.

## i18n added — reversing an earlier call in this same session

Earlier today I recorded i18n as **deliberately not taken**, reasoning that it
"belongs to a project that has two locales, not to a base project that has
none". The user overruled it, and they were right: the expensive part of i18n is
not the library, it is the copy already scattered through two hundred components
by the time anyone decides to add a second language. A base project is exactly
where that gets prevented.

Leaving the earlier entry above as written — it was the decision at the time,
and editing it to look consistent would destroy the only property that makes
this log worth reading.

`docs/I18N.md` covers four stages, each reachable from the previous without a
rewrite:

| Stage | When | Copy lives in |
| --- | --- | --- |
| 0 | one language | `content.ts` — the rule that already exists, now with its reason |
| 1 | 2–3 languages | `messages/<locale>.json` + next-intl, key-parity gate |
| 2 | 4–12 | one table with a `context` column → generated JSON; MT as draft |
| 3 | open-ended | database: `app_texts` + translations with a status workflow |

Read the feldpost implementation properly rather than working from memory. What
carried over, and why each exists:

- **The `context` column.** The thing the user specifically remembered, and the
  load-bearing part of the whole design. `Save` is a verb on a button and a noun
  in a report; a translator given only the word gets it wrong about a third of
  the time, and nobody notices until a native speaker does.
- **Machine output lands as `draft`, never published.** The status column is the
  review workflow; the app reads only `published` and falls back to the source
  language, so a locale can be half-finished in production without ever showing
  a wrong string.
- **Diacritics and mojibake validation.** MT and CSV round-trips produce `ae`
  for `ä`, `ss` for `ß`, unaccented Italian vowels, and `U+FFFD`. These look
  like a rendering bug and are actually bad data.
- **The no-hardcoded-literals gate**, which is what keeps stages 1–3 honest.

### One thing corrected rather than copied

Feldpost constrains the language list with `check (lang in ('en','de'))`, so
adding Italian needed a migration that drops and re-adds the constraint — there
is one in the tree doing exactly that. That does not scale to "indefinite
languages": it is stage 2 wearing stage 3's clothes. `I18N.md` specifies a
`languages` table with a foreign key instead, so adding a locale is one INSERT.
Called out explicitly, because the CHECK constraint looks like good practice
right up until the fifth locale.

Also added, absent from both source projects: ICU plurals rather than
`n === 1 ? … : …` (Polish has three plural forms, Arabic six), `Intl` for dates
and numbers, text-expansion tolerance in layout (German runs 30–40% longer), and
the RTL decision — which has to be made before the layout exists, not after.

### Correction — machine translation starts at stage 1, not stage 2

User: *"No 2-3 languages is also translated by machines dont be funny haha"*.
Correct, and the original framing was quaint — the stage table had stage 1
translated "by humans", which describes a workflow nobody has followed for
years.

The fix was not one table cell. Assuming MT from stage 1 moves two things
earlier and exposes a third:

- **The diacritics and mojibake gate belongs to stage 1.** It was written up
  under stage 2. But bad data enters the moment a *machine* writes a locale, not
  the moment there are many of them — which at two languages is day one.
- **Same-as-source detection** likewise, as soon as there is a locale nobody on
  the team reads.
- **Context has nowhere to live in JSON.** This only became visible once MT was
  assumed at stage 1: `{"upload.save": "Save"}` hands an engine one word and no
  situation. At two locales you catch the bad guess because you read both; the
  moment you stop, it ships. So stage 1 now names the choice explicitly — a
  `_context.json` sidecar, or move to the table early — rather than leaving
  context as something that appears at stage 2 for no stated reason.

What actually distinguishes the stages, once MT is a constant, is **where the
copy lives** and **what catches a bad translation** — not who does the work. The
table column changed from "Translated by" to "How quality is assured", which is
the axis that genuinely varies:

| Stage | How quality is assured |
| --- | --- |
| 1 | you can still read every locale yourself |
| 2 | you cannot — gates and native-speaker review |
| 3 | a status workflow: draft → reviewed → published |

Stage 2 also gained the consequence that follows from all of this: when the
gates are the only thing between a machine and production, a gate failure is a
blocker. Ship without the locale rather than with a bad one — a missing language
falls back to source and is merely incomplete; a wrong one is a wrong statement
in the product's voice.

## Third pass — the source project's own diaries

Read all eleven entries in feldpost's `docs/ai-diary/`, not the five I had
sampled. forju has no diary. What the entries actually record, once the
project-specific detail is stripped out, is a small set of failures repeating
under different names.

### Added to AGENT-PITFALLS

- **§6 Stacking fixes without reverting the failed one.** The most costly
  pattern in the whole diary, and it is named explicitly in one session's own
  focus line: "a long detour caused by layering fixes on top of each other
  without re-checking the baseline". A vertical-alignment bug was chased with
  `top: 2px`, then `translateY(-50%)`, then a margin trick, then a container
  unit — and the actual cause was a `display: flex` added two attempts earlier
  "to help centering". Carries two sub-rules from the same entry: **revert
  before you retry**, and the **two-attempt rule** (stop, summarise, offer two
  options — do not auto-pick a third architecture). Plus: when the user says
  "it works if I turn this off", that is the answer, not a hint.
- **§7 Not making the observation that halves the problem.** An agent debugged
  change detection, portals and extra state while one question — *does the other
  part of the same dropdown update as I type?* — would have proved the state was
  fine and the rendering was not. With the corollary from the same entry: the
  repo already contained a working version of that exact widget, and nobody
  grepped for it until late.
- **Prompting §2:** point at something that already works and name the mechanic.
  Taken from the entry where the user said "like the address row — width and
  height must not change on focus", which the agent recorded as the thing that
  turned taste into a testable invariant.

### Added to TRAPS

- **A token that does not exist resolves to nothing.** An agent rebuilt a state
  machine and its CSS before finding the one-line cause: `--transition-geometry`
  was named in the spec and had been removed in a migration. Now gated —
  `check-tokens` resolves every `var(--x)` against the defined set. Proved it
  bites before trusting it.
- **Tests that pass alone and fail together.** Recorded as cross-file injector
  pollution in one entry and a constructor/`set()` race in another. The rule
  that matters: a flaky test is not a gate.
- **`position: sticky` fails silently without a bounded scroll container.**
- **A controlled input can lose what the user typed.**

### Added to STATE

**§5 Do not write state in an effect that reads it.** Their version was "never
write a signal inside an `effect` that reads it" — the same bug React has with
`useEffect` + `setState`, and it produced a blank page there. Written up as the
general rule: if you can compute it, compute it; effects are for synchronising
with things outside the framework.

### Enforced rather than written down

One entry diagnoses *why* a class of bug was hard: "~6–7/10 from file length;
rest = distributed state and implicit scope" — and the fix was a lint rule
capping service files at 300 lines and functions at 80. Added the same limits
here (`max-lines`, `max-lines-per-function`, tests exempt). It is the only
place in the source projects where someone measured a cause and then gated it,
which makes it worth copying exactly.

### Went wrong

Turning on the size rules surfaced **three lint warnings that had been there all
along** and I had never looked at — two anonymous default exports and one unused
destructured variable. A build that always warns teaches people to skip the
output, which is the same failure as the `AGENTS.md` warning threshold earlier
today. Fixed all three; lint is now silent, so the next warning will be visible.

## Primitives built — the audit's top gap closed

`Field`, `Input`, `Textarea`, `Select`, `Dialog`, `Table`, with UC-002, UC-003,
four specs and 47 tests. The audit put the component library at 20% because the
repo *mandated* patterns and shipped one component implementing them.

Design decisions worth keeping:

- **Field owns the ids; controls read them from context.** Invalid is derived
  from the presence of `error` rather than a second prop — two inputs for one
  state is how a red border and a silent screen reader end up disagreeing.
  Controls still work standalone, so the primitive is not a cage.
- **`aria-invalid` is omitted when valid**, not set to `"false"`. The attribute
  exists to signal a problem; `"false"` on every field is noise.
- **The error is both `role="alert"` and in `aria-describedby`.** Mildly
  duplicated announcement, chosen over silence for a keyboard user whose focus
  is elsewhere at submit time. Written down in the spec as a trade-off, not
  presented as free.
- **Native `<select>` and native `<dialog>`.** The platform ships focus
  trapping, Escape, the top layer, `inert`, typeahead and the mobile wheel
  picker. Rebuilding those is where accessible components usually go wrong.
- **`Table` puts the accessibility rule in the type system**: `caption` is
  required and `Th` cannot be written without `scope`. Review does not have to
  remember what the compiler can.

### Went wrong

- **jsdom does not implement `showModal`.** Checked before designing rather
  than after, which is the one thing that stopped this becoming a rewrite.
  `tests/setup.ts` shims it, and deliberately does **not** fake focus trapping —
  a shim that pretended to would let a genuinely broken modal pass the suite.
  Focus behavior is browser-verified and the spec says so.
- **Wrote a test with a cast to make a wrong API call typecheck**
  (`getAllByRole(/regex/ as unknown as string)`). It failed, correctly. The cast
  was the tell: needing one to call a library function usually means calling it
  wrong. Fixed the call.
- **Two eslint rules were wrong and the code was right** — jsx-a11y does not
  model `<dialog>` as interactive, and it forbids `tabIndex` on a region even
  though WCAG 2.1.1 requires a scrollable container to be keyboard-operable.
  Both got a disable with the FIGHTING/REMOVE comment this repo's own §10
  requires. First real use of that rule on itself.

### Open

Still no theme toggle, so `[data-theme]` remains implied rather than wired. And
the `## Check` for each new spec passes, but none of these components has been
seen in a browser — jsdom cannot render, and the repo has no E2E gate.

# Wood-grain FFT synthesis — session images

Every image generated, transformed, or uploaded while building the 2D-FFT
wood-grain synthesis pipeline. This folder is the visual record; the
reasoning is [`docs/study/STUDY-032-photographic-wood-grain-synthesis.md`](../../docs/study/STUDY-032-photographic-wood-grain-synthesis.md)
and the runnable tool is [`scripts/wood-grain-fourier-synthesis.py`](../../scripts/wood-grain-fourier-synthesis.py).

**Start here if you just want the current best output:** `outputs/final/`.
Everything else is provenance and the iteration trail.

## Structure

```
wood-grain-fourier/
  sources/                   Uploaded originals — nothing here was generated by the pipeline
  patches/                   Cropped single-species source material, fed to the pipeline
  outputs/
    final/                   Current best pipeline output — start here
    exploration/             The iteration trail: every technique tried, kept for reasoning
    data/                    Extracted spectral data (JSON) behind the exploration images
```

## `sources/` — uploaded originals

| File | What it is |
| --- | --- |
| `grid-6up-source.png` | ChatGPT-generated 3x2 grid, 1536x1024 — six wood species in one image (oak, pine, walnut, maple, cedar, ash). The actual source for every patch in this pipeline. **Known limitation:** a multi-species grid splits resolution six ways and creates seams between species — see STUDY-032 evidence. Superseded by generating one wood per image; no single-wood photo has been generated yet (image-generation budget ran out mid-session). |
| `real-wood-reference-comparison.png` | Phone-gallery photo of a cleaner real wood reference the owner compared synthesized output against — cracks read thinner and sparser than what this pipeline was producing at the time. Drove the `FEATURE_SCALE` tuning in the exploration trail. |
| `concept-seed-photo.jpg` | The original screenshot (a card-game material UI) that started the conversation — "turn part of a photo into a waveform, FFT it for octaves." Not a wood photo; kept for provenance of the idea. |

## `patches/` — cropped source material

352x352 crops of each species from `grid-6up-source.png`, cropped well inside
the cell boundaries to avoid seam contamination from neighboring species
(80px margin — see STUDY-032). `oak-512-full-cell.png` is the same oak cell
at its full 512x512, no margin — safe because it's cropped exactly at the
true cell boundary (no neighbor pixels included either way), used to test
whether more source resolution improves output.

`oak_patch.png`, `pine_patch.png`, `walnut_patch.png`, `maple_patch.png`,
`cedar_patch.png`, `ash_patch.png`, `oak-512-full-cell.png`

## `outputs/exploration/` — the iteration trail

Kept because each step answers a specific "why does it look wrong" question;
useful for anyone extending the pipeline or hitting the same failure mode.

**Per-species base grain** (all six woods, before crack layer was added):
- `{species}_spectrum.png` — 2D power spectrum of the real photo
- `{species}_synth.png` — first attempt: radially-averaged spectrum used as
  the synthesis filter. Isotropic — grain direction is lost, reads as
  "mottled noise" rather than streaks. Rejected.
- `{species}_synth_aniso.png` — fix: real (unaveraged) 2D spectrum as the
  filter. Grain direction survives.
- `all_radial_spectra.png` — all six species' radial power spectra overlaid,
  log-log

**Crack layer, oak only** (the detailed path — same techniques apply to the
other species' `{species}_crack_layer.png`):
- `oak_crack_layer.png` — isolated dark-defect residual (`blur(img) − img`)
- `oak_crack_synth_naive.png` — spectrum-matched synthesis of the crack
  layer alone. Diffuse haze, not lines — spectrum only controls pairwise
  correlation, not the sparse/heavy-tailed marginal distribution real cracks
  have. Rejected.
- `crack_histogram_compare.png` — histogram plot proving why: naive
  synthesis is a symmetric bell curve, the real crack layer is a spike at
  zero with a long tail
- `oak_crack_synth_hb.png` — fix: Heeger-Bergen alternating projection
  (spectrum-match + histogram-match). Actual sparse dark scratches.
- `oak_crack_synth_hb_scale4.png` — same, with `FEATURE_SCALE` applied
  (Fourier scaling theorem) to resize crack features
- `crack_radial_spectra.png` — all six species' crack-layer radial spectra

**Rim highlight** (the raised/frayed fiber lip beside a real crack):
- `oak_rim_only.png` — first attempt: symmetric difference-of-Gaussians
  halo. Wrong — lit both sides equally; real light rakes one side only.
  Rejected.
- `oak_rim_directional.png` — fix: vertical gradient of the crack field,
  biased to one side
- `oak_rim_patchy.png` — added a thresholded noise mask so the highlight
  doesn't run a crack's full length

**Full composite iterations** (`oak_card_composite*.png`, v1 → v7): the
progressive tuning pass — crack density, rim strength/patchiness,
`FEATURE_SCALE`, base-grain contrast, each adjusted against direct owner
feedback in sequence. `v4` onward add color (`_color.png` vs `_gray.png` =
shading map before colorizing). `v7` is the last exploration-stage version
before the pipeline was consolidated into the script; `outputs/final/`
supersedes it.

## `outputs/data/`

- `octave_weights.json` — per-species base-grain octave amplitudes, extracted
  from `{species}_spectrum.png`
- `crack_octave_weights.json` — same, for the crack layer, plus
  `crack_energy` (mean defect darkness) per species
